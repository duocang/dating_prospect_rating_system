# 隐私与数据保护

目标：长期积累用户数据的同时，让每个人都能看清、控制、带走、删除自己的资料。下面标注了哪些**已实现**、哪些**上线前必须补**。

## 1. 数据分级

| 级别 | 内容 | 存储 | 对其他用户展示 |
|---|---|---|---|
| L1 基础资料 | 年龄、身高、城市、学历、职业大类、定居、婚育计划、沟通与生活方式 | 加密 | 可原样展示 |
| L2 敏感资料 | 收入、个人与家庭资产、住房、车、其他负债、家庭支持、父母养老、兄弟姐妹、照护、父母婚姻 | 加密 | 金额只显示分档；类别显示选项文字（如“有车，无贷款”“父母离异”），不涉及具体数字 |
| L3 身份资料 | 昵称、“已生成恢复码”标记 | 单独的身份库，加密 | 不展示，从不参与评分。不收手机号；恢复码只存带密钥的哈希（见 AUTH.md） |
| 择偶要求 | 你的理想型 | 加密 | 仅在你同意进入人选池后，以匿名代号展示 |

分级写在 `packages/schema/fields.js` 的 `tier` 上，展示规则集中在 `server/src/present.js`。

## 2. 已实现

- **数据最小化**：服务端只接受字段注册表里的字段和选项，其他内容直接丢弃；性别方向由服务端按异性恋范围设定。
- **静态加密**：资料、要求、身份库都用 AES-256-GCM 加密写盘；明文只有性别方向、套餐、同意记录和时间戳。生产环境必须用环境变量 `VIER_DATA_KEY` 提供密钥，缺少时拒绝启动；开发环境自动生成 `data/.dev-key` 并警告。
- **验证前不上传**：填写过程中答案只存在本机浏览器；输对验证码后才一次性交给服务器。中途离开的人，服务器上没有任何记录。
- **身份与资料分离**：身份信息存放在 `data/vault/`，与 `data/users/` 分开，方便将来放到不同的库、用不同的密钥和权限。
- **按用途同意**：三项分别同意，带版本号和时间，历次记录都保留：
  1. 用我的资料计算我的结果（必选）
  2. 以匿名代号出现在别人的结果里（可选；不同意就不进入真人人选池）
  3. 用于匿名统计（可选）
- **结果只在服务端计算**：浏览器永远拿不到人选池的原始数据，只拿到经过脱敏的卡片和逐项说明。
- **防拼合代号**：同一位人选，在不同查看者眼中的代号不同（HMAC），多人无法拼合同一人的信息；内部 id 不发往浏览器。
- **k-匿名统计**：分布接口只开放基础字段，人数少于 10 的档位合并为“其他”。
- **导出与删除**：“我的数据”页可导出全部资料（JSON），也可永久删除资料、要求、同意记录和身份库。
- **审计日志**：记录创建、保存、同意、计算、导出、删除，主体只记带密钥的哈希，不记资料内容。
- **保留期**：`npm run purge:inactive` 删除超过 365 天（可配置）未活跃的账户。
- **模拟与真人分开**：模拟模式只用模拟档案，真人模式只用同意进入人选池的真人，两者永不混用；模拟档案在页面上逐张标注。
- **管理员可见范围**：持有 `ADMIN_TOKEN` 的管理员可以看到单个用户的全部资料和全部要求（金额为具体数字），用于审核和处理问题；每次查看都记入审计日志 `admin.user_viewed`。
- **基础安全头**：CSP、nosniff、no-referrer；请求体限 64 KB。

## 3. 上线前必须补

- 正式数据库（如 PostgreSQL）替换文件存储，按表做行级权限；身份库放独立的库和密钥，密钥交给 KMS 管理并定期轮换。
- 全站 HTTPS 与会话过期（令牌 90 天不用失效）；换设备靠恢复码，不收手机号。
- 接口限流和防爬：防止有人反复修改理想型来“扫描”人选池。
- 核验材料：只保存核验结论和日期，原件核验后删除，记录在审计里。
- 照片：如需引入，单独同意，只对本人展示或只用于本人审美反馈，不推断健康、民族等敏感特征。
- 法律文本：按《个人信息保护法》准备隐私政策和单独同意（敏感个人信息需单独同意），明确保存期限、境内存储、未成年人排除、第三方共享（目前没有）。
- 删除的备份策略：备份中的数据在固定周期内随备份轮换清除，并在隐私政策中说明。
- 研究导出：只导出去标识、分档后的数据，并做 k-匿名检查。
