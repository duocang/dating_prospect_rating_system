# 命名

## 2026-11-18 起：三个问题 + Z 字图

产品聚焦三个问题，页面用字母 A/B/D 标在 Z 字图上（和宣传图一致），C 是你自己：

| 字母 | 页面名称 | 回答的问题 | 代码 | Z 字位置 |
|---|---|---|---|---|
| B | 你的理想型 | 你喜欢什么样的人 | `idealMatches` | 右上 |
| A | 理想型的理想型 | 你喜欢的人，喜欢谁；你配不配 | `idealOfIdeal`、`myPlaceA` | 左上 |
| C | 你 | — | `me` | 左下 |
| D | 想找你这样的人 | 你这样的人，配谁 | `seekers` | 右下 |

箭头：你 → B → A，D → 你。结果页三个页签顺序 B → A → D。“双向相合”（`mutual`）不再单独成组，只在 B、D 卡片上标“双向”。A 是和你同性别的人，只做对照，不能牵线。A 的口径：取你的前 N 位理想型人选，把同性别人选对这些人的要求分别打分，取平均排序；你本人按同一口径排进去，得到名次。

## 2026-11-15 的命名（取代旧 A / B / C / D 记号）

旧文档用字母和撇号（A、A′、B′、C′、D′）区分“概念”和“具体的人”，用户很难记。新命名直接说出关系。代码、接口、页面统一使用下表。

| 新名称（页面） | 代码中的名字 | 含义 | 旧记号 |
|---|---|---|---|
| 你 | `me` | 本次测试的本人 | C′ |
| 你的理想型 | `myIdeal` / `me.requirements` | 你写下的择偶要求（一组条件，不是一个人） | 概念 B |
| 理想型人选 | `idealMatches` | 人选池中最接近你理想型的真人 | B′ |
| TA 的理想型 | `theirIdeal` | 某位人选自己写下的择偶要求 | 概念 A |
| 你符合 TA 的理想型 | `myFitToThem` | 用你本人的资料对照 TA 的理想型得到的分数（**新增**） | 旧设计没有 |
| TA 心中的人选 | `theirPicks` | 人选池中最接近 TA 理想型的人，与你同一性别；并给出你在其中的名次范围 | A′ |
| 在找你的人 | `seekers` | 你的条件符合其理想型的人。**只表示条件相合，不代表对方有兴趣** | D′ |
| 双向相合 | `mutual` | TA 接近你的理想型，你也符合 TA 的理想型（**新增**） | 旧设计没有 |

关系图保留 Z 字形：左上“TA 心中的人选”，右上“理想型人选”，左下“你”，右下“在找你的人”。路径是 你 → 理想型人选 → TA 心中的人选，以及 在找你的人 → 你。

## 为什么“在找你的人”不叫“对你有兴趣的人”

我们只有对方填写的条件，没有对方真实的互动或选择。条件相合 ≠ 兴趣。等将来有真实互动数据（例如对方主动查看或标记），再单独建一个“对你有兴趣”的信号，不和条件分数混在一起。
