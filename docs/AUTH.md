# 账户与恢复码

没有手机号、没有密码。填写过程中答案只存在浏览器里（`localStorage` 的 `vier.draft`），服务器上不建账户、不留任何记录；填完并同意后输一次图片验证码，通过了服务端才建匿名账户，把资料、要求和同意记录一次存好，返回令牌（`vier.token`）。之后改资料和以前一样直接存到服务器。

- 不用登录也能填写资料、看结果。没过验证就离开的人，服务器上什么都没有。
- 已经有令牌的老用户不受影响；只存在本机的草稿继续在本机填写。
- 恢复码要有服务器上的账户，所以验证之前不能生成（首页、最后一步、我的资料里显示“完成验证后可以生成”）。没过验证时“换个人，从头开始”只清掉本机草稿。
- 换手机或清了浏览器，令牌就没了。想找回，要先在旧设备上生成一个**恢复码**。
- 恢复码 12 位，显示成 `XXXX-XXXX-XXXX`，去掉了 0/O、1/I/L 这些容易看错的字符；输入时不分大小写，横线和空格可有可无。
- 明文只在生成时显示一次。再生成一次，旧码立即作废。
- 在新设备上输入恢复码：服务端发新令牌，旧设备上的令牌失效；新设备上刚开的匿名会话不保留。

## 入口

- 首页（已开始填写后）：“存个恢复码，换手机也能找回” / “重新生成恢复码”；点“换个人，从头开始”时，没存过恢复码会先提示存一个。
- 最后一步（`#/consent`）：“换手机也想找回？”（已验证的账户才有按钮）。
- 验证码（`#/verify`）：同意之后、看结果之前。答错会抖一下、自动换一张。
- 我的资料（`#/privacy`）：“恢复码”和“用恢复码找回”。
- 找回页：`#/recover`（首页“已经填过？用恢复码找回”）。

## 存储

- `data/recovery-index.json`：带密钥的 HMAC（`recovery:` + 规范化后的码）→ 用户 id，不存明文。
- 身份库里只记一个标记 `recovery: true`，用于界面提示和“空账户清理”时不删存过恢复码的账户。
- 删除账户时，索引里的那一条一起删掉。

## 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/captcha` | 不需令牌。返回 `{ id, svg }`；按 IP 每小时 60 次 |
| POST | `/api/session` | 不需令牌。`{ captchaId, answer, gender, profile, requirements, consent: { adult, scoring, pool, research }, identity: { nickname } }` → `201 { token }`。没有或答错验证码、资料不合格、未确认 18 岁都返回 `400`，不建账户；按 IP 每小时 30 次 |
| POST | `/api/me/recovery` | 需令牌。生成新恢复码，返回 `201 { code }`；旧码作废 |
| POST | `/api/recover` | 不需令牌。`{ code }` → `200 { token }`；码不对返回 `400`；按 IP 每小时 10 次 |

`GET /api/me` 里的 `hasRecovery` 表示是否生成过恢复码。

## 验证码

- 服务端零依赖生成 SVG：字是手画的折线字库（不用 `<text>`），每个字随机旋转、平移、缩放、抖动，加几条干扰线，路径顺序打乱，不带任何能看出答案的元数据。
- 5 位，字符去掉 0/O、1/I/L，以及折线下容易混的 G、Z；不分大小写。
- 内存里只存答案的哈希，5 分钟过期，每分钟清理一次；一次性：验过一次不管对错都作废，答错要换一张。
- 测试：`createApp({ ..., onCaptcha })` 可以传一个回调，在进程内拿到明文答案，只给自动化测试用。HTTP 接口上任何模式（包括 `testMode`）都拿不到答案，也没有固定的测试答案，所以配置写错也不会留后门。
