# 账户与进入

没有手机号、没有密码、没有自助注册。账户由管理员在后台建好，只登记号（微信号、小红书号、抖音号，至少一个）；本人凭其中任何一个号进来填写。

## 流程

1. 管理员在后台点“新建用户”，填号（`POST /api/admin/users`）。这时账户是空的。
2. 本人在首页点“开始填写”（或“已经填过”），进入 `#/start`：选号的种类、输号、输图片验证码。
3. 服务端先验验证码，再查号（不分大小写）：
   - 号没登记：`404`，页面提示“还没登记，请联系我们”。
   - 账户还空着（没选过性别）：直接发令牌，开始填写。之后每答一题都直接存到服务器。
   - 账户已经填过：返回 3 道题和一张 10 分钟有效的通行证。3 道题从 TA 在“介绍自己”里答过的题中，按服务端密钥固定挑出，每次都一样。
4. 答题 `POST /api/start/answer`：3 道都对（年龄、身高允许差 1）才发令牌；答错不提示是哪道。同一个号连续答错 3 次，锁 24 小时（存在内存里，重启清零）；答对一次清零。
5. 发新令牌时，旧设备上的令牌失效。

为保证填过的人有题可问，“介绍自己”至少要答 3 道（年龄、身高、城市、学历等，见 `RECALL_KEYS`）：填写时剩下的题凑不够 3 道就不能再跳过；同意“用我的资料计算结果”时服务端也会检查；改资料时不能删到 3 道以下。

空账户被别人抢先冒填时，管理员可以在详情面板点“清空资料，让 TA 重填”（`POST /api/admin/users/:id/reset`）：资料、要求、同意记录清掉，号保留，所有设备退出。

## 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/start` | 不需令牌。`{ kind: wechat\|xhs\|douyin, handle, captchaId, answer }` → 空账户 `{ token }`；填过的 `{ questions, pass }`；没登记 `404` |
| POST | `/api/start/answer` | 不需令牌。`{ pass, answers }` → `{ token }`；答错 `400`，锁住 `429` |
| POST | `/api/admin/users` | 管理员。`{ nickname?, wechat?, xhs?, douyin? }`，至少一个号；号已被登记 `409` |
| PUT | `/api/admin/users/:id/handles` | 管理员。改号或称呼 |
| POST | `/api/admin/users/:id/reset` | 管理员。清空重填 |

本人不能改自己的号，只能改昵称。

## 验证码

- 服务端零依赖生成 SVG：字是手画的折线字库（不用 `<text>`），每个字随机旋转、平移、缩放、抖动，加几条干扰线，路径顺序打乱，不带任何能看出答案的元数据。
- 5 位，字符去掉 0/O、1/I/L，以及折线下容易混的 G、Z；不分大小写。
- 内存里只存答案的哈希，5 分钟过期，每分钟清理一次；一次性：验过一次不管对错都作废，答错要换一张。
- 测试：`createApp({ ..., onCaptcha })` 可以传一个回调，在进程内拿到明文答案，只给自动化测试用。HTTP 接口上任何模式（包括 `testMode`）都拿不到答案，也没有固定的测试答案，所以配置写错也不会留后门。
