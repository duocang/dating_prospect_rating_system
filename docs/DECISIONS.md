# 关键决策与理由（2026-11-15）

以下是本次重构中做出的取舍及理由，每条都可以调整。

1. **多位人选各有自己的理想型 → 用切换，不合并。** 结果页列出理想型人选；点进去后顶部用“人选 1 / 2 / 3”标签切换，每页展示 TA 的理想型、你符合多少、TA 心中的人选。合并成一个“平均理想型”会抹掉每个人真实的要求，也无法逐项解释。总览页另给一个“你与理想型人选的理想型平均契合度”，作为整体印象。

2. **数量：免费每组 3 位，VIP 每组 5 位。** 写在 `config/app.json`，四组可分别设置。升级 VIP 通过扫码支付（微信支付 Native / 支付宝当面付），弹窗显示二维码，支付成功后自动升级；未接入商户前用模拟支付走通流程，见 PAYMENTS.md。价格 ¥1.99，VIP 暂为长期有效。

3. **新增“你符合 TA 的理想型”分数和“你在 TA 心中人选里的名次范围”。** 这是用户最想知道、旧设计没有直接算的数。名次用区间表示，因为资料有未知或分档时无法给出精确名次。

4. **“双向相合”单独建模**，按两个方向分数下界的几何平均排序。几何平均让任何一边偏低都会拉低整体，比算术平均更符合“双向”的含义。

5. **“在找你的人”排除要求少于 3 项的人。** 要求很少的人几乎对谁都给满分，放进榜单会误导。被排除的人数会在结果页说明。

6. **理想型人选同分时，优先展示你也更符合其理想型的人。** 模拟库里大量人选会并列 100 分，按编号排序没有意义；用反向契合度打破并列更有用，且不改变分数本身。

7. **未知不当 0，覆盖率低于 70% 不进正式排序。** 防止只填了一两项、恰好满分的人排到最前。

8. **资料整体加密落盘，分级只决定对他人的展示粒度。** 原先打算 L1 明文、L2 加密，但婚育计划等 L1 项也相当私密，整体加密成本很低。

9. **结果只在服务端计算。** 浏览器拿不到人选池，降低被爬取和拼合的风险。

10. **零第三方依赖。** 用户的电脑和服务器都能直接 `npm start`，没有安装步骤；以后换数据库或框架时只动 `server/` 内部。

11. **旧网页全部移入 archive，不删除。** 宣传图、研究资料、模拟库生成器也在其中，新模拟人选池由脚本从 archive 转换，可复现。

12. **服务范围保持异性恋。** 服务端按性别自动设定寻找方向，不接受其他方向的输入，与项目既有约定一致。

13. **真人与虚拟人选放在同一个池子里。** 不再区分演示模式和真人模式：100 城各有 500 位男性、500 位女性虚拟人选，按城首次用到时生成并缓存（固定种子，可复现）；真人同意进入人选池后直接加入。虚拟人选在卡片上标“虚拟”，不能牵线。“未来定居”选项改为不绑定上海的说法。

14. **（2026-11-18）定位聚焦三个问题，A 合并成一组。** “你喜欢的人，喜欢谁”需要一组明确的人，所以把每位理想型人选各自看中的人汇总：对每位理想型人选的要求分别打分再取平均，没达门槛按 0 算，至少对一半理想型人选达标才入榜。每位理想型人选自己的“心中人选”仍在详情页保留。互相适合不再单独成组，改为卡片小标，减少一个页签，让结果页和 Z 字图一一对应。
