## 当前产品边界

- 这只是前端原型，没有真实账户、数据库、付费、身份核验、真实匹配或联系其他用户的能力。
- C 是填写者示例；A、B、D 及十五份人物档案、插画头像、百分比分数都是虚构内容。分数不是恋爱成功概率，也不是人本身的价值。
- 产品当前服务范围只包含异性恋用户；当前原型按女性寻找男性展示 Z 字关系。模拟与表单样例按女性寻找男性、男性寻找女性设置，不提供同性配对选项。此范围不构成对未来扩展的承诺。
- 早期产品建议先给匿名统计与期待差距，不开放私信或见面匹配。

## 网页和小程序怎么选

第一阶段建议先用手机优先网页跑通问卷、完成率、用户授权与反馈流程。网页可通过链接和二维码传播，改字段和文案也更快。正式托管仍要根据运营主体、域名、服务器和服务类型核对 ICP 备案及其他要求。

小程序适合验证后接入微信生态，分享路径短，也有更一致的移动端体验；但需要主体账号、类目审核、微信登录与支付方案、服务端和域名配置。工信部 APP 备案通知把小程序写入相关分发生态，具体备案路径须按运营主体和服务形态向主管部门及微信平台核实。小程序并不必然比网页上线快。

建议顺序：

1. 用 v3 手机优先网页做小范围邀请内测，先不公开发布。
2. 用 100–200 人/城市的试点检查问卷完成率、数据缺项、重复提交和用户是否信任数据说明。
3. 确定字段、授权文本、统计方法和付费逻辑后，再把已验证流程移植到小程序。

## 小程序原型

`miniprogram/` 是可导入微信开发者工具的前端页面骨架。项目使用本地虚构样例，没有服务端、实名认证、支付或真实资料。导入后先用开发者工具预览，正式申请前需填写自己的小程序 AppID 并配置服务端和合法域名。
