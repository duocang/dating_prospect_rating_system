# VIER 首批真人试点与身份核验准备

2026-11-13。N05 交付：方案与服务选择依据；尚未申请服务、接入真实资料、启用付款或结算。建议先上海一城，前100份有效真人档案做小试，再累计到500份；这是建议，不是固定招募承诺。

## 先设计一套网页和小程序共用的审核流程

1. **体验与贡献分开。** 体验入口可先看示例；申请首批贡献资格或提交用于真实统计的档案时，明示用途、展示范围、审核与更正规则。不能把手机登录标成实名核验。
2. **基本身份与去重。** 手机验证码确认可控制该号码，服务端向经确认可用的供应商核对姓名、证件号、手机号一致性，再按核验身份做跨网页/小程序的唯一贡献资格。三要素一致不保证当前操作者就是本人。借用身份、家庭共用号码、查无记录等进入人工补核，不按一个失败码认定欺诈。
3. **首批更严格。** 系统检查重复、缺项、口径和矛盾。审核员根据必要性核对本人出示的来源材料，如学历、收入期间及范围，并做简短访谈。后续用户也做基础核验；有异常或高影响字段缺证据时进入复核，不因付费跳过审核。
4. **核验按字段记录。** 保留状态、来源类别、有效日期和必要审核理由；证件核验与档案展示分开。家属婚姻、资产、照护等允许自述或跳过，外貌和偏好不盖客观真实章。资料可靠性、择偶拟合和分红资格用不同状态表示。
5. **通过后进入有效样本。** 审核状态为待审、待补充、通过或拒绝，允许更正。按通过审核的唯一真人计数。起始100份用于检查题目理解、缺项和审核耗时；关键口径变更后补答，达到同一口径的资料才并入500。不同招募渠道、年龄/性别及普通职业收入要有覆盖，不能只在相亲炫耀帖上招募。

## 服务准备与可行选项

| 网页或小程序共用的运营商三要素服务 | [阿里云运营商三要素](https://help.aliyun.com/zh/cpns/product-overview/three-element-verification)核对姓名、手机号、证件号，官方场景列有交友婚恋；[详版接口](https://help.aliyun.com/zh/id-verification/information-verification/developer-reference/rmzw1b9yiux29e5g)需开通，能区分一致、不一致、查无记录 | 首选询价与资质确认。由自己的后端调用，避免凭证出现在网页或小程序代码；供应商资格、费用和实际开通以其审核为准 |
| 腾讯云微信小程序人脸核身 | [腾讯云 FAQ](https://cloud.tencent.com/document/product/1007/45893)明确写婚恋行业小程序不支持；[开通手册](https://cloud.tencent.com/document/product/1007/132597)还有发布与类目条件 | 不把这一方案列为婚恋类小程序上线依赖；不通过改报类目规避。VIER 具体业务分类应向平台确认，不能据此推论所有第三方或所有网页方案都不支持 |
| 网站 H5／其他供应商实人服务 | 存在技术产品，但 VIER 的公司主体、场景权限、正式服务环境尚未核对开通 | 先走最少必要的非人脸方案，不能把人脸作为可被同等方式替代时的唯一手段；确需更强复核时再核资质、处理依据、单独同意与影响评估。见[人脸识别技术应用安全管理办法](https://www.cac.gov.cn/2025-03/21/c_1744174262156096.htm) |
