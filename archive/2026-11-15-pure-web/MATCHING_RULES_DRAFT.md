# VIER 逐字段拟合计算建议 v0.1

2026-11-13。状态：可实现的算法草案，尚未用真人数据验证；本轮未替换网页或数据库的现有计算代码。整理依据为当前默认网页、上海模拟库、留学生版已采字段和用户最新说明。

## 1. 已确定的含义

拟合分衡量某份档案相对于目标画像条件的接近程度。它不是个人价值评分，也不是对方真实喜欢或关系成功的概率。

用户已明确：目标年收入 10 万元、候选收入 9 万元，则收入这一项为 90%。这一规则保留。身高不能用 170/180 得到 94.4% 来代表该项拟合，需要独立的差值换算。

现有 generate.mjs 的 evaluate 只有 11 项二元重合加权，收入未达到下限时该项直接不重合；这并非用户现在要求的细分算法。现有示例 Z 路径还刻意寻找三条边均 100 分的链，只能当演示，不能拿来验证新算法。

## 2. 通用函数和规则

- 金额达标比例 R(x,t)=100×min(1,max(0,x)/t)，t>0。收入采用此规则：9/10=90，18/20=90。超过目标暂建议封顶 100，避免一个项目无限加分；这是产品建议，不是用户已经确认的超额收入规则。目标为 0 表示未设金额要求，跳过此项，不能除以零。要求某个收入区间时改用区间规则。
- 数值差距先求 d：理想区间 [L,U] 内 d=0；区间外为到最近边界的距离。单点目标 d=|x-t|；至少 t 的要求 d=max(0,t-x)；至多 t 的要求 d=max(0,x-t)。输入必须区分“至少、至多、约、范围”。
- 差距评分 G(d,D)=100×max(0,1-d/D)，D>0。D 是该字段以原单位表示的扣分尺度；身高用 cm、年龄用年、时间用月，不统一用原始数值比例。线性是首版可解释基线，也应比较分段曲线。身高 D=20cm 时，目标 180、实际 175 得 75，实际 170 得 50；D=10cm 时实际 170 得 0。这些都是说明公式的情景，不是已验证参数。需要校准的是 D 和曲线形状，不能伪称 170cm 天生就是某个契合分。
- 无序类别用“目标类别/可接受集合”判断，或使用用户明确选择的理想/可接受/不接受矩阵；100/60/0 可作演示矩阵，60 仍是待验证的产品参数。不得把不同家庭背景、职业、性格本身排成普适的高低分。
- 多选标签采用“命中的目标标签权重/目标标签总权重”×100；候选额外有别的兴趣不自动扣分。排斥项单独处理。用户未提出相关期待时该字段不计分。
- 区间或分档资料保留评分区间。例如净资产 50–100 万、目标至少 100 万，只能支持该项约 50–100 分的区间，不能擅取 75 万冒充精确值。区间重叠可能导致排序无法分辨，应显示并列或信息不足。
- “必须”是独立门槛，不是更大的权重；有钱不能抵消用户明确的生育计划冲突。未满足和未知必须条件分别标记。严格满足者不足五人时说明不足；若提供偏离要求的参考档案，要明确指出，不能暗中放宽。

## 3. 普通版逐字段建议

| 字段 | 建议计算 | 补充说明 |
|---|---|---|
| 年收入 | 金额比例 R | 统一期间、税前/税后和收入类型；低于目标按比例，超目标封顶是建议 |
| 身高 | 数值差距 G，单位 cm | 单点、至少或范围分别求 d；D_h 和曲线需校准 |
| 年龄 | 理想年龄区间 + 超出年数的 G | 区间内达标；不做 28/30 这种年龄比例 |
| 体重 | 用户明确的体重/体型偏好区间 + 差距 G | 可选；不把越轻当越好，不从体重推断健康或性格 |
| 体型 | 用户选择的类别集合/多选特征 | 与身高体重有重叠，控制同组权重；不要重复加分 |
| 外貌自评 | 不直接跨人计算 | 不把两个人自打的 7 分当同一尺度；无本人审美反馈时显示自述/未知，不能 AI 编造客观颜值 |
| 个人照片 | 用于展示和经授权的个人审美反馈，不直接数值相除 | 如以后收集 C 对匿名档案卡的选择，另建个人审美偏好；不推断照片中的健康/身份等敏感特征 |
| 已取得学历 | 要求下限或明确类别集合 | 本科及以上：本科、硕士、博士均满足，不默认博士比本科多加 3 倍分；低于要求的部分得分需事先定义 |
| 在读学历/学业阶段 | 与已取得学历分开，按目标阶段集合 | 硕士在读不能直接记为已获硕士 |
| 职业/行业 | 目标职业、可接受行业集合或明确的分类矩阵 | 不按行业声望任意打分；职业名称先规范到同一分类 |
| 工作状态/稳定性 | 类别匹配；若采集波动、工时则分别按数值或区间 | 创业/自由职业不自动低分，需与用户的明确要求对照 |
| 当前常住城市 | 目标城市/可接受城市集合 | 同城要求是门槛或类别匹配；城市名不能算数字相似度 |
| 城市生活时长 | 有最低要求才按年/月差距 G 或门槛 | 无该偏好仅用于样本口径 |
| 户籍 | 独立的类别集合，用户有明确要求才使用 | 不把户籍与家乡混成一项，不推导经济条件 |
| 家乡/成长地 | 地域类别或可接受集合 | 不自动给城市高于农村的分数 |
| 婚恋状态 | 允许的明确类别集合/门槛 | 未婚、离异、有无子女分开，不把未知当未婚 |
| 已有子女 | 数量区间或接受集合/门槛 | 与未来是否想生育分开 |
| 本人住房 | 所有权、居住安排、贷款状态、购房计划拆开后各自类别匹配 | 住父母房不等于本人有产权；房产净值若已计净资产不得重复计经济权重 |
| 个人净资产 | 正数目标可用 R；输入分档时给评分区间 | 先扣本人债务、按产权份额，不计父母尚未转移的资产；负值需单列，不能进行负数比例 |
| 个人存款 | 若有独立现金储蓄要求用 R | 净资产已包含存款时，不把同一财富重复多计 |
| 个人负债/还款 | 债务类型按集合；还款额/收入比按上限差距或门槛 | 目标为零债务时不可除以零；贷款金额与现金流压力不同 |
| 家庭净资产 | 同口径下的 R 或分档评分区间 | 与个人资产分开；家产不能自动当成可供用户支配的资金 |
| 父母住房 | 产权/贷款/居住安排按集合 | 不自动当成 C 本人的可用婚房；避免与家庭资产重复计分 |
| 家庭资金支持 | 有明确金额时用 R；只有类别时用集合/矩阵 | 支持意愿、可供金额和实际已取得资金分开 |
| 情感/日常协助支持 | 类别或具体行为集合匹配 | 不能和首付支持混为同一条从差到好的量表 |
| 父母养老保障 | 保障类型/经济赡养安排按集合；金额另算 | 养老金、医保、需要子女提供多少钱拆开，不用一个模糊“支持度” |
| 父母健康与照护责任 | 比较实际照护安排、频率、时间或支出与用户要求 | 不把父母健康状态直接当人的价值分，也不由照片推断健康 |
| 父母婚姻状态 | 用户明确的接受集合；未提要求则不计分 | 离异、丧偶等没有默认低分；法律婚姻状态与家庭相处状况分开 |
| 兄弟姐妹 | 是否有/人数按明确集合或区间 | 独生不自动 100、有手足不自动 50；照护和经济责任单独记录 |
| 家庭债务 | 类型集合；确有金额/偿还义务时按上限差距 | 只计实际相关的责任，不用全家贷款总额重复扣分 |
| 家庭成员独立/边界安排 | 对居住、经济支持、决策参与等具体安排做类别匹配 | 不用一句“原生家庭好”由 AI 任意打总分 |
| 家庭成长环境 | 只有明确偏好才类别匹配，否则展示信息 | 无城市/县镇/乡村的通用优劣顺序 |
| 未来定居/迁居计划 | 目标城市、可协商范围和时间计划的组合匹配 | 与当前同城分开；共同落脚地可行性要单独显示 |
| 结婚时间 | 将双方期望转成时间区间，比区间是否重叠；不重叠按相隔月/年用 G | “暂无计划”“先相处”是类别/不确定，不能乱填一个年份 |
| 是否想生育 | 明确类别匹配/门槛 | 想生与不生不能被高收入补偿；尚未决定不等于同意 |
| 沟通/性格 | 具体特征集合、情境题或明确相处偏好矩阵 | 相似不一定就是契合，不默认外向优于内向 |
| 冲突处理与独立空间 | 行为/安排类别或题目级匹配 | 把“需要冷静后沟通”与“不愿沟通”区分 |
| 吸烟 | 接受集合或门槛 | 不吸烟/吸烟/戒烟中等明确分类，不与喝酒绑成一个字段 |
| 饮酒 | 频率/量的区间和接受类别 | 少量/经常需有定义；不直接借吸烟一项重复加减分 |
| 作息/工作时间 | 可相处时间区间的重叠与明确作息要求 | 是否同频依据具体时间，不只靠“规律”标签 |
| 兴趣/宠物/社交活动 | 分拆后的目标标签加权覆盖；明确排斥单列 | 额外兴趣不自动扣分；养宠与能否接受宠物分开 |
| 家庭情况补充/其他文字 | 仅辅助提取候选字段，并由填写者确认 | 不用整段文字的语义相似度代替资产、婚育等事实匹配；不从文字擅自补缺失事实 |

## 4. 留学生版补充字段

| 字段 | 建议计算 |
|---|---|
| 留学国家/地区 | 目标及可接受地区集合；不设国家价值排名 |
| 当前学业阶段 | 明确阶段类别集合，与已完成学历分开 |
| 预计毕业时间 | 日期/区间的差距 G；已经毕业为事实状态、未知不造日期 |
| 毕业后留当地/回国倾向 | 未来地域和可协商计划的类别/组合匹配 |
| 异地接受度 | 当前距离情景、预计持续时间、能否结束异地的明确规则；不用公里数直接相除 |
| 语言沟通 | 双方可深入沟通语言的交集、熟练程度是否达到明确要求 |
| 跨文化沟通意愿 | 与语言能力拆开，按明确意愿类别比较；不依据国籍推测 |
| 学生收入 | 当前实际收入与家庭生活费、奖学金、未来预期收入分开；仅对同口径目标算 R |

## 5. 不计入拟合分的记录信息

昵称、编号、联系方式、提交时间、问卷版本、设备风控线索、付款/免费资格、实名认证结果、凭据和核验日期，用于展示、联系授权、去重、口径、审核或权益，不计择偶分。异性恋服务范围和希望认识的性别用于关系方向/范围筛选，不折算成“性取向分”。没有该字段偏好的数据仅用于画像说明，不为了凑总分全部强行打分。

资料是否已核验、资料覆盖率与条件拟合分分别显示。未披露不是 0 分，不可按默认值补成满足；用户没提出某项要求时跳过该项。

## 6. 汇总、缺失和前五名

先查明确门槛，再计算单项分。已知且适用项目的总分为 sum(w_i*s_i)/sum(w_i)，权重来自用户的重视程度并归一化；初版参数需公开。各大组设权重，再在组内分配，防止收入、房产、存款、净资产、家庭支持重复把经济条件加五次。

同时给出加权资料覆盖率：已知适用权重/全部适用权重。低覆盖者不能靠一项已知满分进入榜首；门槛字段未知者待核实。排序池的最低覆盖率需要单独设产品规则（例如 80% 是候选方案，不是研究认证线）。分档导致分数区间重叠时保留不确定性/并列，不伪造 99.97% 区分。

收入 10 万目标、候选 9 万得 90；身高 180 目标、175cm 在示例 D_h=20 下得 75；年龄理想 28–32、候选 31 得 100；本科及以上且候选本科得 100；同城要求满足得 100。若示例权重为 30%、20%、15%、15%、20%，总分为 92/100。这是验证算式的例子，不证明这组权重和身高尺度符合真实偏好。若身高 180 是明确硬门槛，该候选不能作为“满足门槛者”被高收入补偿入选。

五人取当前合格池中相对最接近者，允许不完全符合、允许并列、也允许没有足量合格记录；不能硬造五个高分或按排名预设 99、98、97 分。

## 7. 概念与具体人的记号（用户已确定，不重新研究 Z 图关系）

- 不带撇的 A、B、D 表示概念画像；A′、B′、D′ 表示具体档案。同一概念下五人可写 A′₁…A′₅、B′₁…B′₅。
- C′ 是本次测试的具体客户。平台不另造一个独立的“概念 C”。旧文口头称 C 的客户，现在统一按 C′ 理解。
- B 是 C′ 自己提出的理想条件；计算具体 B′ 与概念 B 的逐字段及总体拟合度。
- A 来自具体 B′ 自己提出的理想条件；计算具体 A′ 与概念 A 的拟合度。切换具体 B′ 后，引用其本人的要求，不替他编造要求。
- 具体 D′ 也有自己填写的理想伴侣条件，用真实 C′ 的资料去核对；这些条件可以不同，不需要先造一个统一 C 概念。
- 本项研究重点是概念与具体档案之间如何逐字段计分、加权和解释前五名。既定 Z 图关系和布局沿用用户设定，不作为需要重新论证的课题。

## 8. 下一步验证与交付

数据库部分负责逐字段评分函数、参数字典、算例和排序解释；网站部分负责把组合输入拆成可计算字段，补齐“约/至少/至多/范围、明确门槛、重视程度”等信息。视频仅提供待验证字段/情境，不作为身高差几厘米扣几分的唯一依据。

先比较少数可解释曲线和权重情景，报告哪些改动会改变前五名；检查单位一致、范围内得分、单调性、零目标、负资产、未知值、硬条件、并列和 Z 方向。当前模拟数据可查程序逻辑，不能验证真人偏好准确性。后续以真人对档案的独立评价校准曲线，按人划分评估，区分自报偏好和实际档案兴趣。

本轮已增加算法设计需求，应优先交付评分方案和可解释算例，再按剩余时间安排数据库界面/造数改版，不为了赶八小时随意定参数。正式替换前保留原算法版本及参数；此文不构成已获验证的定稿。
